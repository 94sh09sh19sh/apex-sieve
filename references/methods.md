# Apex Sieve 方法參考

執行時遇到需要細節的地方再查這份文件。

## 1. 理論對應

| 步驟 | 理論 | 重點 |
|---|---|---|
| 0、2、3 | 一般形態分析（Zwicky 1969；Ritchey 2011） | 先用多條參數軸定義整個組合空間（形態箱），再用交叉一致性評估（Cross-Consistency Assessment）兩兩剔除不可能的值對 |
| 0、3 | 最佳化理論的可行域 | 先用限制式圈出可行域，再在可行域內找最優 |
| 3 → 6 | 兩階段決策：非補償式 → 補償式 | 第一階段只看有沒有違反限制，優點多也救不回來（Tversky 1972 逐項刪除法；Beach 1990 映像理論的相容性檢驗）；第二階段準則可互相彌補（MAUT、SMART） |
| 4 | Keeney 1992 價值焦點思考 | 不只在既有選項中挑，而是主動創造更好的選項 |
| 6 | 多屬性效用理論（MAUT）、SMART／SMARTER（Edwards & Barron 1994） | 準則要可加（偏好獨立）、要有錨點、權重要反映「範圍」而不只是「重要性」 |
| 7 | 決策分析的敏感度分析 | 權重與分數都有不確定性；結論要對合理範圍內的擾動穩健 |
| 8 | 組合決策分析（Portfolio Decision Analysis；Salo, Keisler & Morton 2011） | 選 k 個時，最佳組合不等於前 k 名；要考慮互補、重複、預算 |
| 9～11 | 決策品質（Decision Quality；Spetzler 等 2016） | 決策品質的六個要素：適當的框架、有創意的選項、可靠的資訊、清楚的價值取捨、合理的推論、承諾行動 |

## 2. 權重方法

設有 n 條條件，依重要性排出名次 i = 1…n（1 最重要）。

| 方法 | 公式 | n = 4 的權重 | 特性 |
|---|---|---|---|
| 等權重 | wᵢ = 1/n | .25／.25／.25／.25 | 只在真的分不出輕重時用 |
| 名次加總（rank-sum） | wᵢ = (n − i + 1) / Σ | .40／.30／.20／.10 | 權重差距平緩，第二名的分量相對大 |
| 名次重心（ROC） | wᵢ = (1/n) Σⱼ₌ᵢⁿ (1/j) | .52／.27／.15／.06 | 理論上是「只知道順序」時的期望權重，第一名的分量明顯較大 |
| 名次倒數 | wᵢ = (1/i) / Σ | .48／.24／.16／.12 | 介於兩者之間，尾端保留較多分量 |
| 擺盪權重（swing） | 見下 | 依使用者回答 | 最嚴謹，權重反映「這條從最差變到最好值多少」 |

**擺盪權重的問法**：
1. 想像有一個選項，所有條件都是最差（1 分）。
2. 如果只能把一條條件從最差拉到最好（5 分），你會先拉哪一條？這條給 100。
3. 其他條件依序問：「把這條從最差拉到最好，相對於第一條值多少？」給 0～100。
4. 正規化成總和 1。

**為什麼要問「範圍」而不是「重要性」**：如果所有候選在某條條件上都差不多，這條再重要也不會影響排名。擺盪權重自然把這件事算進去。

## 3. 偏好結構的一致性

| 使用者的說法 | 實際的偏好結構 | 對應做法 |
|---|---|---|
| 「A 最重要，B 次之…」 | 可能是加權，也可能是字典序 | 追問：「A 差 1 分，B 要多幾分才能補回來？」答得出來 → 加權；「補不回來」 → 字典序 |
| 「A 是主軸，其他都是副產品」「衝突時照順序裁決」 | 字典序 | 用字典序；或設 A 的門檻後，其餘加權（混合） |
| 「A 不能太低，其他看總分」 | 混合 | A 設門檻（搬到步驟 3 當軟限制門檻），其餘加權 |

**一致性快速檢驗**：用加權算出的排名中，如果有某個選項在使用者口中的「主軸」條件上明顯較差，卻因為其他條件排到前面，就把這個例子拿給使用者看，問他能不能接受。

## 4. 限制的分類

| 來源 | 預設類型 | 例子 |
|---|---|---|
| 法規、倫理審查 | 硬 | 個資法、人體試驗規範 |
| 物理限制 | 硬 | 記憶體容量、電池續航、裝置尺寸 |
| 競賽規則、合約 | 硬 | 指定硬體、繳交期限、評分辦法中的資格條件 |
| 委託方明確要求 | 硬 | 客戶明定資料不得上雲 |
| 資源上限 | 硬（但上限本身可議） | 預算、人力、時程 |
| 自己推論而來的要求 | **軟** | 「最好能用上最新的框架」（實際上是加分條件） |
| 程度問題 | **軟＋門檻** | 「不能太複雜」→「規則說明超過 3 頁就剔除」 |
| 和其他選項重複 | **不是限制** | 留到步驟 8 處理 |

**判斷口訣**：違反它，是「做不到」還是「不想選」？「做不到」才是硬限制。

## 5. 切軸的檢查表

- [ ] 參考了這個領域的專業分類方式，並寫明出處
- [ ] 每條軸只有一種層級（不能機制和題材混在一起）
- [ ] 每條軸的值互斥且窮盡，3～7 個
- [ ] 各軸的值數量與粒度相近
- [ ] 兩兩軸之間低相關（某軸的值不會幾乎決定另一軸的值）
- [ ] 有一條不參與交叉的反向檢查軸
- [ ] 格子總數可處理（必要時先做值對相容性剔除）

**相關性的判斷方式**：對軸 A 與軸 B 畫出值對矩陣，估計其中有意義的組合比例。
- 大部分組合都有意義 → 低相關
- 約一半有意義 → 中相關，檢查是否某個值對另一軸有強烈偏好
- 只有對角線附近有意義 → 高相關，兩軸其實在量同一件事，要合併或換軸

## 6. 均勻取樣

**目標**：每條軸的每個值，在選項清單中出現的次數大致相等，避免某些區塊因為比較容易想到而被過度代表。

**做法**：
1. 可行格子 ≤ 60：每格至少 1 個選項，格子少時每格 2～3 個。
2. 可行格子 > 60：用分層取樣。先算每條軸每個值應出現的目標次數（總樣本數 ÷ 該軸值數），再挑格子，讓實際次數接近目標。這和拉丁超立方抽樣、正交表的精神相同：用較少的樣本覆蓋每條軸的每個值。
3. 列出覆蓋表，若某個值的次數明顯偏低，補樣本。

**建議樣本量**：總共約 30～120 個具體選項。太少會漏，太多評分品質會下降。

## 7. 錨點的寫法

壞的錨點：「1 分＝差，3 分＝普通，5 分＝好」。

好的錨點（以「容易上手」為例）：
- 1 分：看完說明仍不知道怎麼開始，需要別人帶
- 3 分：看完說明後 10 分鐘內能完成第一次操作
- 5 分：不看說明就能完成第一次操作，且之後會主動再用

判斷標準：兩個人拿同一份錨點獨立評分，大部分分數相差不超過 1 分。

## 8. 合併的判斷

兩個選項適合合併，需同時符合：
1. 核心不衝突（例：一個要快節奏、一個要慢節奏 → 衝突）
2. 優點互補（各自在不同條件上拿高分）
3. 合併後的複雜度仍在限制內
4. 合併後的核心價值仍然清楚（不會變成什麼都有、什麼都不精）

合併後一律重新跑限制檢查與評分，不能直接把兩邊的高分相加。

## 9. 停損條件的寫法

壞的停損條件：「效果不好就換」。

好的停損條件：
- **指標**：新使用者首次任務完成率
- **門檻**：連續兩輪測試低於 50%
- **檢查時間點**：第一輪使用者測試後、第二輪使用者測試後
- **觸發後的動作**：換成備案 B2，保留已經完成的共用元件
